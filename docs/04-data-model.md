# 04: Data Model

The data lives in two places:

1. **PostgreSQL:** identity, access control, project metadata, binary document snapshots, versions.
2. **Yjs document (one per project):** all diagram content. This is the collaborative state.

## 1. PostgreSQL schema (Drizzle)

Better Auth owns `user`, `session`, `account` and `verification` (generated by its CLI). Our tables:

```sql
-- Projects
CREATE TABLE projects (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name          text NOT NULL CHECK (char_length(name) BETWEEN 1 AND 200),
  description   text,
  owner_id      text NOT NULL REFERENCES "user"(id),
  thumbnail_key text,                         -- MinIO object key
  archived_at   timestamptz,
  deleted_at    timestamptz,                  -- soft delete, purge after 30 days
  created_at    timestamptz NOT NULL DEFAULT now(),
  updated_at    timestamptz NOT NULL DEFAULT now()  -- bumped by collab on store
);

-- Membership & roles
CREATE TYPE project_role AS ENUM ('owner', 'editor', 'commenter', 'viewer');
CREATE TABLE project_members (
  project_id  uuid REFERENCES projects(id) ON DELETE CASCADE,
  user_id     text REFERENCES "user"(id) ON DELETE CASCADE,
  role        project_role NOT NULL,
  added_by    text REFERENCES "user"(id),
  created_at  timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (project_id, user_id)
);

-- Invitations (email) and share links
CREATE TABLE project_invites (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id  uuid REFERENCES projects(id) ON DELETE CASCADE,
  email       citext,                -- NULL for link invites
  role        project_role NOT NULL CHECK (role <> 'owner'),
  token_hash  bytea NOT NULL UNIQUE, -- sha256 of random token
  expires_at  timestamptz,
  max_uses    int,
  uses        int NOT NULL DEFAULT 0,
  created_by  text REFERENCES "user"(id),
  revoked_at  timestamptz,
  created_at  timestamptz NOT NULL DEFAULT now()
);

-- Current collaborative state (one row per project)
CREATE TABLE project_documents (
  project_id   uuid PRIMARY KEY REFERENCES projects(id) ON DELETE CASCADE,
  state        bytea NOT NULL,        -- Y.encodeStateAsUpdate
  schema_ver   int   NOT NULL,        -- @cld/model doc schema version
  size_bytes   int   NOT NULL,
  updated_at   timestamptz NOT NULL DEFAULT now()
);

-- Immutable history
CREATE TABLE project_versions (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id  uuid REFERENCES projects(id) ON DELETE CASCADE,
  state       bytea NOT NULL,
  label       text,                   -- NULL = autosave
  kind        text NOT NULL CHECK (kind IN ('auto','manual','import','restore')),
  created_by  text REFERENCES "user"(id),
  created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX ON project_versions (project_id, created_at DESC);

-- Activity log (who did what, coarse-grained)
CREATE TABLE project_activity (
  id          bigserial PRIMARY KEY,
  project_id  uuid REFERENCES projects(id) ON DELETE CASCADE,
  user_id     text REFERENCES "user"(id),
  type        text NOT NULL,          -- 'joined','imported','exported','version.saved',...
  payload     jsonb,
  created_at  timestamptz NOT NULL DEFAULT now()
);

-- User preferences
CREATE TABLE user_preferences (
  user_id     text PRIMARY KEY REFERENCES "user"(id) ON DELETE CASCADE,
  theme       text NOT NULL DEFAULT 'system',
  cursor_color text,                  -- else derived from user id
  prefs       jsonb NOT NULL DEFAULT '{}'
);
```

Retention for autosave versions: keep everything for 24 h, then hourly for 7 days, then daily for 90 days. Compaction runs as a worker job. Manual and import versions are kept forever.

## 2. Yjs document schema (`@cld/model`)

All IDs are `nanoid(12)` strings generated on the client. Ordering uses **fractional indexing** (`fractional-indexing` package) stored as string keys, so concurrent reorders never conflict the way array moves would.

```
Y.Doc (guid = project:<uuid>)
├── meta: Y.Map
│   ├── schemaVersion: number
│   ├── name: string                       (mirrors projects.name for export)
│   ├── defaults: Y.Map  (default node/link style for new elements, theme)
│   └── vensim: Y.Map    (passthrough of unknown MDL sections, see 07)
│
├── variables: Y.Map<variableId, Y.Map>     # semantic entities (model level)
│   └── { id, name, notes?, units?, mdlExtra? }
│
├── diagrams: Y.Map<diagramId, Y.Map>
│   └── {
│        id, name, order (fractional key),
│        background?: color, grid?: { size, visible, snap },
│        layers: Y.Map<layerId, Y.Map{ id, name, order, visible, locked, opacity }>,
│        elements: Y.Map<elementId, Y.Map>   # see element types below
│      }
│
└── comments: Y.Map<threadId, Y.Map>
    └── { id, diagramId, anchor: {elementId?} | {x,y}, resolved, resolvedBy?,
          createdBy, createdAt,
          messages: Y.Array<Y.Map{ id, authorId, body (markdown-lite), mentions[], createdAt, editedAt? }> }
```

### Element types (inside `diagram.elements`)

Every element has the common fields:

```ts
interface ElementBase {
  id: string;
  type: 'variable' | 'link' | 'loop' | 'shape' | 'text';
  layerId: string;
  z: string;               // fractional index within layer
  locked?: boolean;
  createdBy: string;
  mdl?: Record<string, unknown>;  // raw unknown MDL fields for round-trip
}
```

| Type | Fields |
|------|--------|
| **variable** (node) | `variableId` (→ `variables`), `x, y` (center), `w, h`, `form: 'none' \| 'rect' \| 'rounded' \| 'ellipse' \| 'pill'`, `isShadow` (ghost copy of a variable placed primarily elsewhere), `style: NodeStyle` |
| **link** (causal arrow) | `from: elementId`, `to: elementId`, `control: {x,y} \| null` (null = straight; else the arc passes through this point, matching Vensim), `polarity: '+' \| '-' \| '?' \| 'S' \| 'O' \| null`, `polarityPos: 'head' \| 'tail' \| 'middle'`, `polaritySide: 'auto' \| 'left' \| 'right'`, `delay: boolean`, `label?: string`, `style: LinkStyle` |
| **loop** (marker) | `x, y`, `r` (radius), `kind: 'R' \| 'B' \| 'custom'`, `label: string` (e.g. "R1"), `name?: string` (e.g. "Equipment sharing"), `direction: 'cw' \| 'ccw'`, `linkedCycle?: elementId[]` (links forming the loop, from analysis), `style` |
| **shape** | `shape: 'rect' \| 'rounded' \| 'ellipse' \| 'diamond' \| 'line' \| 'arrow'`, `x, y, w, h, rotation`, `text?`, `style` |
| **text** | `x, y, w`, `text` (rich-lite: bold/italic/links), `style` |

Links connect **elements**, not variables. The semantic graph (variable → variable) is derived as `link.from → element.variableId`. That lets a diagram contain shadow copies, and lets the same causal relation show up in two views.

### Style objects

```ts
interface NodeStyle {
  fill?: Color | null;          // null = transparent
  stroke?: Color | null;
  strokeWidth?: number;         // 0..8
  strokeDash?: 'solid' | 'dashed' | 'dotted';
  textColor?: Color;
  fontFamily?: 'sans' | 'serif' | 'mono' | 'hand';
  fontSize?: number;            // 8..72
  fontWeight?: 400 | 600 | 700;
  italic?: boolean;
  align?: 'left' | 'center' | 'right';
  opacity?: number;
  shadow?: boolean;
}
interface LinkStyle {
  color?: Color; width?: number; dash?: 'solid'|'dashed'|'dotted';
  head?: 'arrow' | 'triangle' | 'open' | 'none';
  polarityColor?: 'auto' | Color;  // auto: + uses positive theme color, − negative
}
type Color = string; // '#rrggbb' or theme token 'token:accent-3'
```

Unset style fields fall back to `meta.defaults`, then to the built-in theme. That keeps documents small and lets a theme change restyle everything.

### Invariants (checked by `@cld/model/validate`)

- A link's `from` and `to` must exist in the same diagram. Deleting a node deletes the links attached to it in the same transaction.
- `variables[*].name` is unique when compared case-insensitively with whitespace collapsed. MDL requires this. The UI warns on a clash and offers "use existing variable (create shadow)".
- A variable with no remaining node in any diagram gets garbage-collected (in the delete transaction).
- Every element references an existing layer. Deleting a layer either deletes its elements or moves them, depending on the user's choice.
- Each diagram has at least one layer.

Concurrent edits can break these (e.g. user A deletes a node while user B draws a link to it). **Repair runs on observe:** every client runs `repair()` after remote transactions and drops dangling links. The repair is idempotent, so several clients doing it at once converge.

### Document schema migrations

`meta.schemaVersion` is checked in collab `onLoadDocument` and in the client. Migrations are pure functions `(doc: Y.Doc) => void` that run in one transaction with origin `'migration'`. A client running an older version than the document refuses to edit and shows "Please reload".
